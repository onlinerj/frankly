# Issue #476: Calendar event URL as location

Captured September 8, 2026 from the actual Dart CalendarLinkUtil with a fixed event fixture. These screenshots show a report of generated output, not an authenticated Google or Microsoft calendar UI. No external calendar events were created.

## Observed results

| Format | Before | After |
| --- | --- | --- |
| Google Calendar | Location omitted | Event URL in location |
| Office 365 | Location omitted | Event URL in location |
| Outlook | Event URL already present | Event URL preserved |
| ICS download | LOCATION omitted | LOCATION contains event URL |
| Community ICS feed | LOCATION omitted (regression test) | LOCATION contains event URL (regression test) |

The screenshots and raw export files cover the first four formats. The feed is checked separately by the existing emulator-backed integration test.

## Artifacts

- before.png / after.png: browser screenshots of the captured export report.
- before.json / after.json: exact generated calendar links and ICS text from the original/fixed utility.
- before.ics / after.ics: downloadable ICS output.
- before.html / after.html / index.html: locally viewable evidence reports.
- calendar_link_evidence_test.dart: temporary capture harness that invokes the real utility; not part of the application PR.

The sample event uses the repository's test domain, localhost:5000. Its URL is a fixture, not a deployed public meeting. The existing HTTPS URL format is unchanged. ICS UID and DTSTAMP are generated by the installed library and can differ between runs.

## Reproduction

From firebase/functions/, use the project's configured Node and Dart toolchains and installed dependencies. Copy the capture harness to test/utils/calendar_link_evidence_test.dart, then run:

```sh
CLOUD_RUNTIME_CONFIG=./test/test_config.json dart test test/utils/calendar_link_evidence_test.dart --reporter expanded
```

The CALENDAR_EVIDENCE line contains the unmodified generated outputs as JSON. Compare location query parameters and the ICS LOCATION property before and after the code change. Unfold ICS continuation lines before inspecting long properties. Remove the temporary harness after capture.

## Validation

The regression suite consists of four utility tests and one extended community feed test. Against the original implementation, Google Calendar, Office 365, and ICS utility checks failed; Outlook passed. The feed test also failed because LOCATION was missing. All five pass with the fix.

Run with a Firestore emulator and a separate test project, since the existing feed fixture clears data within its selected project:

```sh
GCLOUD_PROJECT=demo-frankly-476 \
FIRESTORE_EMULATOR_HOST=localhost:8080 \
CLOUD_RUNTIME_CONFIG=./test/test_config.json \
dart test --concurrency=1 test/utils/calendar_link_util_test.dart test/events/calendar/calendar_feed_ics_test.dart
```

The tests also check preserved descriptions, title query encoding, ICS start/end times, and the feed URL property.

The Cloud Functions build passed. Focused analysis found no errors or warnings and two existing informational diagnostics for package:js imports missing a direct dependency declaration. No new diagnostics remain. git diff --check passes.

## Implementation

Expose location in the calendar-link JavaScript interop model and populate it from the same URL as description. Outlook's custom URL builder reads the location field. Add location to the separate community ICS feed model, using the same URL as its existing URL property. No package changes, configuration changes, or migrations are required.
